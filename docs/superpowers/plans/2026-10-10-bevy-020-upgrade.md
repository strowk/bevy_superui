# Bevy 0.20 Upgrade (0.4.x track) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `main` to `0.4.0` / bevy 0.20, re-vendoring `bevy_flair` 0.9 (from git) into the `superui_flair_*` forks, reconciling fork patches, and porting the workspace to the 0.20 API.

**Architecture:** Lean delta on the 2026-07-25 bevy-0.19 upgrade — all infra (single `[workspace.dependencies]` bevy knob, renamed `superui_flair_*` forks, fork-patch registry + `xtask fork-patches`, `xtask publish`, compat table, `CONTRIBUTING.md`) already exists and is reused as-is. The sequence is: re-vendor flair 0.9 vanilla → reconcile patches (drop 2, rework 1, reapply 3) → flip the one version knob + `cargo set-version 0.4.0` + bump ecosystem crates → build-fix loop against the 0.20 API (with an explicit query/resource-conflict audit) → tests + native/wasm smoke → docs → verify + handoff. No boa work (the engine is V8 now; the boa forks are gone). No branch cut (`release/bevy-0.19` already exists).

**Tech Stack:** Rust workspace, Bevy 0.19→0.20, vendored `bevy_flair 0.9` fork (from git `main`), `cargo-edit` (`cargo set-version`), `xtask` (plain-arg CLI), mdBook (`website/`), `bevy_egui`, `bevy_brp_extras`.

**Spec:** `docs/superpowers/specs/2026-10-10-bevy-020-upgrade-design.md`

## Global Constraints

- **Work on `main`.** No worktrees (the `target/` dir is huge — the project CLAUDE.md forbids them). Do **not** push. Do **not** publish. The maintainer handles push + publish.
- **Version scheme:** `0.1.x`=bevy 0.17, `0.2.x`=bevy 0.18, `0.3.x`=bevy 0.19, `0.4.x`=bevy 0.20. All crates share `version.workspace = true`.
- **Branch cut already done:** `release/bevy-0.19` exists and is pushed. Do not re-cut it. Backports now flow **only** to `release/bevy-0.19`; `release/bevy-0.18` and `release/bevy-0.17` are **frozen**.
- **Ecosystem pins (verified live 2026-10-10):** `bevy`/`bevy_*` → `0.20`; flair vendor base → `main` @ a pinned commit (package 0.9.0); `bevy_egui` → `0.43.1`; `bevy_brp_extras` → `0.23.0`.
- **Vendor flair from git, not crates.io.** flair 0.9 is not published (crates.io max is 0.8.1 = bevy 0.19). Clone `https://github.com/eckz/bevy_flair`, pin the resolved commit SHA, copy source. flair `main` pins `bevy = 0.20.0-rc.1`; we override all bevy deps with `{ workspace = true }` (= `0.20`), so the rc pin does not follow.
- **Fork versions stay on OUR track (0.4.0), never 0.9** — a fork version above the workspace version creates a wrong-track `cargo add` trap. `set-version` won't downgrade; manual-bump if numbers cross.
- **Fork-patch markers (exact):** `// >>> SUPERUI-FORK-PATCH: <id>  (docs/fork-patches.md#<id>)` … `// <<< SUPERUI-FORK-PATCH: <id>` (for Cargo.toml use the `#`-comment form).
- **Patch reconciliation (the core delta):** DROP `css-eof-guard` (upstreamed, flair PR #58) + `css-import-relative-resolution` (flair 0.9 fixed it); REWORK `css-rem-unit` to the `text.rs` line-height arm ONLY (drop the `ui.rs`/`parse_val` arm — flair 0.9 + bevy 0.20 do `Val::Rem` natively); REAPPLY `flair-macros-vendored-name`, `slider-part-pseudo-elements`, `slider-default-layer`.
- **Crate count:** 17 publishable crates (no boa). `xtask/tests/publish_order.rs` already asserts 17 — do **not** change it.
- **Never auto-publish.** Claude drives to build/test-green + manifest-sane and stops; never runs `cargo publish` or `xtask publish --execute`. The `xtask publish` dry-run is NOT a green gate — on a version bump it is expected to stop at the first crate whose bumped `0.4.0` sibling isn't on crates.io yet (that is normal, not a defect).
- **Known-ignored on verify:** the Windows main-thread stack-overflow integration suites and the GPU/microbench `#[ignore]` tests are expected non-green / skipped; do not chase them.
- **Disk watch:** `target/` hit ~274 GB / disk-full during the 0.18 rebuild — check free space before the big 0.20 build; `cargo clean` if low.
- **DRY / YAGNI / frequent commits.** Preserve upstream flair attribution (NOTICE + per-crate metadata + the upstream `github.com/eckz/bevy_flair` URL). Commit convention: summary = what; body = why (not a diff restatement).

## Review Focus

Input classes / failure modes the spec implies that the per-task build+unit tests may not exercise, most-likely-to-bite first. Each has a test pinned to its owning task.

- **Broad query vs. resource conflict panicking at startup** (Resources-as-Components era): a `Query<()>`/`Query<Entity>`/`Query<Option<&T>>` system that also reads a resource can panic at runtime, past a green build. → Task 4 audit + the reconcile-path test in Task 5.

- **wasm build on bevy 0.20** (the `engine-web` JS path, no V8): the wasm target must still compile. → Task 5 wasm smoke.
