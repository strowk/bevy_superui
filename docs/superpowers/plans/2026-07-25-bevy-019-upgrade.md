# Bevy 0.19 Upgrade (0.3.x track) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a third published track — cut `release/bevy-0.18` from the current publish-ready `main`, then move `main` to `0.3.0` / bevy 0.19, re-vendoring flair 0.8.0 and porting the workspace to the 0.19 API.

**Architecture:** This is a **lean delta** on the 0.18 dual-track work — all infra (single `[workspace.dependencies]` bevy knob, renamed `superui_flair_*` forks, fork-patch registry + `xtask fork-patches`, `xtask publish`, compat table, `CONTRIBUTING.md`) already exists and is reused as-is. The upgrade is: branch-cut → re-vendor flair 0.8.0 + reapply patches → flip the one version knob + `cargo set-version 0.3.0` + bump ecosystem crates → build-fix loop against the 0.19 API (with an explicit query/resource-conflict audit) → docs → verify → handoff.

**Tech Stack:** Rust workspace, Bevy 0.18→0.19, vendored `bevy_flair 0.8.0` fork, `cargo-edit` (`cargo set-version`), `xtask` (plain-arg CLI), mdBook (`website/`), `bevy_egui`, `bevy_brp_extras`.

## Global Constraints

- **Work on `main`.** No worktrees (the `target/` dir is huge). Do **not** push. Do **not** publish. The maintainer handles push + publish.
- **Version scheme:** `0.1.x`=bevy 0.17, `0.2.x`=bevy 0.18, `0.3.x`=bevy 0.19. All crates share `version.workspace = true`.
- **Branch first:** cut `release/bevy-0.18` from the publish-ready `main` **before** any version change.
- **Ecosystem pins (verified live 2026-07-25):** `bevy`/`bevy_*` → `0.19`; flair fork base → `0.8.0`; `bevy_egui` → `0.41.1`; `bevy_brp_extras` → `0.22.1`.
- **Fork versions stay on OUR track (0.3.0), never 0.8.0** — a fork version above the workspace version creates a wrong-track `cargo add` trap. `set-version` won't downgrade; manual-bump if numbers cross.
- **Fork-patch markers (exact):** `// >>> SUPERUI-FORK-PATCH: <id>  (docs/fork-patches.md#<id>)` … `// <<< SUPERUI-FORK-PATCH: <id>`.
- **Never auto-publish.** Claude drives to dry-run-green and stops; never runs `cargo publish` or `xtask publish --execute`.
- **Known-ignored on verify:** the Windows main-thread stack-overflow integration suites and the GPU/microbench `#[ignore]` tests are expected non-green / skipped; do not chase them.
- **Disk watch:** `target/` hit ~274 GB / disk-full during the 0.18 rebuild — check free space before the big 0.19 build; `cargo clean` if low.
- **DRY / YAGNI / TDD / frequent commits.** Preserve upstream flair attribution (NOTICE + per-crate metadata + the upstream `github.com/eckz/bevy_flair` URL).

- [ ] **Step 2: Pre-seeded 0.19 breakage checklist (reference while fixing)**

Ranked by likelihood of hitting superui (from the Bevy 0.18→0.19 migration guide):

1. **Resources-as-Components.** `#[derive(Resource)]` now also implements `Component`; `#[derive(Component, Resource)]` double-derive is illegal → split the types. Broad queries (`Query<()>`, `Query<Entity>`, `Query<Option<&T>>`) now conflict with resource access in the same system → add `Without<…>` filters or narrow the query. (See the dedicated audit, Step 3.)
2. **Reflect reorg.** Modules exposed at crate root (`array`, `enums`, `list`, `map`, `set`, `structs`, `tuple`, `tuple_struct`); `DynamicStruct::index_of`→`Struct::index_of_name`; `FieldIter` yields `(&str, &dyn PartialReflect)`; `ReflectResource` now also reflects `Component`.
3. **Text.** `TextFont.font: Handle<Font>→FontSource` (use `.into()`); `font_size: f32→FontSize` (wrap `FontSize::Px(...)`); `TextLayout::new_with_justify/linebreak/no_wrap`→`justify`/`linebreak`/`no_wrap`; `Font::try_from_bytes`→`from_bytes` (no `Result`).
4. **Input focus.** `InputFocus.0` no longer public → `get()`/`set(entity)`/`clear()`.
5. **`bevy_scene` — N/A** (resolved in Task 2: flair 0.8.0 dropped it, nothing uses it; the root workspace dep was removed in Task 3).
6. **Feature reorg.** `audio` no longer implied by `2d`/`3d`/`ui`; `bevy_input_focus`/`custom_cursor` moved feature collections; `bevy_picking` no longer implies `bevy_input_focus` (→ `ui_picking`); `experimental_ui_widgets`→`bevy_ui_widgets`, `experimental_bevy_feathers`→`bevy_feathers`. Touches examples + test_engine feature lists and `superui_flair_core`'s `bevy_ui` `features = [...]`.
7. **`Node.direction`** — new required field on exhaustive `Node { … }` literals (`crates/superui/src/mount.rs`, `crates/superui_flair_core/src/impls.rs`, `crates/superui_flair_style/src/components.rs`, `crates/superui_test_engine/src/host.rs`). Prefer `..default()`.
8. **Asset API.** `AssetPath::resolve(&str)`→`resolve(&AssetPath)`/`resolve_str(&str)`; `Assets::get_mut`→`AssetMut<A>`; `AssetPath::get_full_extension`→`Option<&str>`; advanced loads via builder. Recheck the 0.18-era ones persist: `LoadContext::path()`→`.path().path()`, `AssetSource::build()`→`AssetSourceBuilder::new()`, `#[derive(TypePath)]` on loaders, `set_attribute` taking `Cow`.
9. **Smaller:** `ResMut`/`World::resource_mut` require `Mutability = Mutable` bound; `Ref` now `Clone/Copy` (`ref.clone()` returns `Ref<T>`, use `ref.as_ref().clone()`); `DefaultErrorHandler`→`FallbackErrorHandler`; `System::type_id`→`system_type`; `UiWidgetsPlugins`/`InputDispatchPlugin` now in `DefaultPlugins` (remove manual adds); `App::init/insert_non_send_resource`→`init/insert_non_send`.
